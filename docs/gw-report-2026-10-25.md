```
  ▲ 누른 뒤 3분간 3초마다 결과 확인(평소 30초)        │
  │                                                   ▼ 확장 gw-agent 1.5.2 (매장 PC 크롬)
  │  08~22시: 최소화 대기 창에 GW 로그인 → 경영정보 → MIS 주문등록 + 자동 대기(mis-agent.js), 3~5초마다 시트 확인
  │           요청 오면 열린 MIS에서 바로 — 발주: mis.js(그룹 열기 → QT_ORDER → fn_Save → 다시 불러와 대조)
  │                                        Gross: mis-sales.js(매출현황 → MiscellaneousReport → 조회 → Gross 열, MIS엔 저장 안 함)
  │  그 밖: 창 없이 30초마다 확인 → 요청 오면 창 열어 처리 → 닫음 (12분 넘으면 닫고 같은 요청 2번까지)
  │  크롬 자체가 꺼져 있으면: 지킴이 gw-watch.ps1이 5초마다 시트 보고 크롬을 켬 (미검증)
  └─ 시트 misPush{done/error, saved/total, text} · salesPush{done, text} · misAgent{at} ◀─ 결과
```
mis.js·mis-agent.js·mis-sales.js는 GitHub Pages에서 매번 새로 받음 → 확장 재설치 없이 고침. 아이디·비밀번호는 확장의 `chrome.storage.local`(그 PC)에만, 로그인 시도는 30분에 2번까지.

## 5. 내일(월 10/26) 첫 실제 저장 시험 절차
1. **08시 이후**: 폰 발주 탭 "그룹웨어 자동입력" 칸이 "PC 자동 대기 중 · HH:MM 확인"인지. PC 작업표시줄에 최소화된 MIS 창, 확장 팝업 "✓ 대기 중".
2. **발주 확정** 뒤 [GW 전송 N] → 확인창의 품목·수량 목록이 보낼 것과 같은지 보고 확인.
3. **폰 상태**: "PC가 받는 중…" → "PC에서 그룹웨어 입력 중…" → "✓ HH:MM 그룹웨어 저장 완료 N/N개". 대기 창이 있으면 1분 안(추정 — 오늘 Gross 21초, 안내문 기준 10초 안팎). "⚠ 확인 필요"면 눌러서 글을 보고 그대로 전달.
4. **MIS에서 직접 대조**: 주문현황(또는 주문등록 그룹 다시 열기)에서 그룹별 수량이 앱과 같은지. 특히 **앱에 없는데 MIS에 남은 품목**(10/24 시험 등심 10EA 등 — 앱은 안 지움).
5. **확인 포인트**: ① saved/total = N/N ② 그룹(온세물류·새싹농산 …)마다 "그룹: n/n개 저장" ③ 확장 팝업 기록에 "폰 전송 → 대기 창에서 바로 입력" ④ (선택) 수량 바꿔 재전송 → 바뀐 수량으로 덮어쓰고 같은 품목은 "이미 같음" ⑤ 앱 마감 14:30, MIS 마감은 MIS가 판단 — 마감 뒤 전송은 "주문 가능 시간이 아니에요"로 끝나야 정상.
6. 실패하면 확장 팝업 기록(최근 30줄) 캡처 + 폰 "확인 필요" 글 → 팀장. 북마크 "앱 발주 넣기"로 수동 저장은 그대로 가능.

5. **Apps Script 교체 → 3초 폴링** — 20:19 실제 API에 `?ver=1`을 물어본 결과 `ver` 없음(미지원) 확인. 그래서 확장은 5초마다 시트 전체(약 370KB)를 받음: 08~22시 기준 하루 최대 약 10,000회·3.7GB(계산값). 버전만 답하는 Apps Script로 바꾸면 3초 확인 + 바뀐 때만 전체 받기(코드는 이미 대응). 구글 할당량 위험은 추정.
6. **중복 로그인·세션 만료** — 대기 창이 GW·MIS 세션을 계속 들고 있음. 같은 계정으로 다른 PC에서 로그인하면 끊길 수 있음(추정). 끊기면 6분 뒤 GW부터 다시 들어가지만 로그인 시도는 30분 2회까지라 반복되면 그 시간은 멈춤.
