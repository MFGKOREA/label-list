## 2. 응답 속도 SLA

| 경우 | 기준 | 세는 법 |
|---|---|---|
| 단일 자료 즉답(재고·근태·예약·매출) | **3초 안** | 질문을 받은 시각 → 첫 글자가 나간 시각 |
| 2중 전달(다른 AI·시트·화면을 한 번 더 거침), 복합 계산 | **10초 안** | 요청 접수 → 최종 답 |
| 늦어질 것 같을 때 | 시작하면서 "몇 초 걸립니다"를 먼저 보냄 | 답이 늦는 것보다 침묵이 더 나쁨 |
| 모든 보고 | 걸린 시간을 **초 단위로** 붙임 (`1.4초`, `7초`) | 어림수(`금방`, `조금`) 금지 |

지키는 방법(11/13 KM 하달):
- 브라우저·대용량 파일을 매번 직접 훑지 않습니다. **로컬 초경량 캐시 한 번 조회** 또는 **미리 만들어 둔 색인**으로 답합니다.
- 캐시가 지금보다 과거이거나 영업 중이면, 원본 숫자를 그대로 읽지 않고 **경과 소진량을 뺀 `예상 O.O개`**로 답합니다.
- 3초·10초를 넘겼으면 다음 보고에 왜 넘겼는지 한 줄 남깁니다. 같은 이유로 두 번 넘기면 6장(멈춤)으로 갑니다.

## 3. 대장님 피클 입출구 전달 규칙

대장님(전현정 KM, `@jeonhyeonjeong8`)께 가는 말은 피클을 지나갑니다. 모양을 고정합니다.

**답 모양(순서 고정)**

```
결론: 한 줄 (숫자면 숫자까지)
근거: 무엇을 어디서 봤는지 + 본 시각
확인 필요: (있을 때만) KM이 정해야 하는 것 1~3개
```

- **출처·시각은 지우지 않습니다.** 파일 경로, 시트 이름, 화면 이름, 관측 시각을 그대로 둡니다. 요약하면서 빼면 그 답은 못 믿습니다.
- **고객 정보는 일절 쓰지 않습니다.** 예약 보고는 **팀 수·인원 수만**(런치/디너 구분). 이름·연락처·객실·요청사항 금지.
- 호칭은 **'대장님'**. '매니저님'으로 부르지 않습니다.
- 일반 보고는 **보내기 전에 먼저 확인**합니다. 다만 위임된 자동 전달(정례 BOH 리포트, 문의 즉답, AI 공용 게시판 릴레이)은 확인 없이 바로 보냅니다. 이때도 **사족·인사치레 없이 리포트만**.
- 공유 범위는 **개인정보·보고사항 외 전달 금지**.
- 모르면 **'모름'**, 짐작이면 **'추측'**이라고 적습니다. 숫자에 출처가 없으면 보내지 않습니다.
- KM이 정하기 전에는 결제·전화·전송·배포를 하지 않습니다(CLAUDE.md 6·7번).

**들어오는 길**: 대장님 질문 → 피클이 유형을 나눔(직통 즉답 / 게시판 릴레이) → 답은 위 모양으로.
같은 질문이 30분 안에 다시 오면 새로 계산하지 않고 앞 답을 그대로 씁니다(시각만 갱신).

## 4. 표준 태스크 패킷 (일 맡기는 형식)

일은 자연어 지시서만 보내지 않고, 아래 칸을 채운 JSON 한 덩어리로 보냅니다.
스키마: `docs/aside/task-schema.json` · 예시: `docs/aside/task-packet.example.json` · 검사: `python3 tools/ci-checks.py --packets`

| 칸 | 뜻 | 규칙 |
|---|---|---|
| `task_id` | 일 번호 | `T-YYYYMMDD-NNN` (그날 세 번째면 `-003`) |
| `intent` | 무엇을 끝낼지 | **동사 + 끝났는지 보는 기준**을 한 문장에. "조사해줘"가 아니라 "규격 2종을 찾아 표로, 출처 링크 포함" |
| `assigned_to` | 맡는 AI | `claude-code` · `aside` · `remi` · `gpt` · `pickle` |
| `verify_by` | 검증할 AI | 만든 AI와 **다른** AI. 보통 `gpt` |
| `sla_sec` | 끝내야 하는 시간(초) | 단일 자료 3, 2중·복합 10. 더 걸리는 일은 30·60처럼 실제 값을 적음 |
| `retry_count` | 지금까지 실패한 횟수 | 실패마다 +1, 처음은 0 |
| `max_retries` | 실패 상한 | **항상 3** (고정) |
| `status` | 지금 상태 | `queued` → `running` → `verifying` → `done` / `blocked` / `failed` |
| `evidence` | 실제로 돌려 본 것 | 명령과 결과, 파일 경로, 본 시각. **안 해 본 것은 적지 않음** |

상태 흐름:

```
queued ──▶ running ──▶ verifying ──▶ done
              │             │
              └──▶ blocked ◀┘        (3회 실패·KM 결정 필요)
                     │
                     └──▶ failed     (원인 남고 다시 할 수 없음)
```

`blocked`로 바뀔 때는 `blocked_reason`에 한 줄, `evidence`에 마지막 시도와 오류를 남깁니다.
같은 일을 두 번 시키지 않으려고, 패킷은 `docs/aside/tasks/`에 파일로 남깁니다(끝난 것도 지우지 않음).

## 5. 작업 라우팅

| 작업 | 맡는 곳 | 왜 |
|---|---|---|
| 정해진 계산·조회·알림(발주 계산, 재고, 근태 집계, 예약 집계, 86 위험) | **코드**(앱·`order-src/auto/*.mjs`·파이썬) | 같은 입력에 같은 답, 토큰 안 씀, 3초 안 |
| 단순 파싱(JSON·표·정해진 글자 뽑기) | **로컬 스크립트** | AI 판단이 필요 없음 |
| 코드 생성·수정·시험·PR·배포 준비 | **클로드 코드** | 시험 통과 뒤에만 손댐 |
| 집 PC 브라우저·로그인 옆 작업·웹 조사·스크린샷 | **어사이드 / 레미** | 화면을 보는 일은 집 PC가 함(로그인은 KM) |
| 반박·검증·체크리스트 판정 | **GPT** | 만든 AI가 자기 일을 채점하지 않음 |
| 폰 알림·승인 카드·대장님 창구 | **피클** | KM·대장님이 이미 쓰는 통로 |
| 규칙 밖 판단, 값이 모자란 일, 되돌릴 수 없는 일 | **KM** | 짐작으로 채우지 않음(AGENT.md 4장) |

라우팅 3원칙:
1. 같은 일을 두 AI가 동시에 하지 않습니다(한 일에는 한 담당).
2. **만든 AI가 자기 일을 검증하지 않습니다.**
3. 값이 모자라면 멈추고 묻습니다. 빈칸을 짐작으로 채우지 않습니다.

## 6. 서킷 브레이커 — 3회 실패하면 멈춘다

**세는 법**: 같은 태스크에서 **같은 원인**(같은 오류 문구, 같은 막힘)으로 실패한 횟수.
원인을 고쳐 다시 하는 것은 새 시도이므로 0부터 셉니다. `retry_count`가 이 값을 들고 다닙니다.

**3회가 되면**
1. 더 돌리지 않습니다. 똑같은 명령을 네 번째로 실행하지 않습니다.
2. `status`를 `blocked`로, `blocked_reason` 한 줄, `evidence`에 마지막 시도·오류를 적습니다.
3. 할 수 있는 다른 길(다른 AI·다른 방법)을 한 줄 적습니다.
4. 요청자(KM 또는 지시한 AI)에게 **원인 1줄 보고**: "무엇을 3번 했고, 매번 무엇이 막혔고, 다음에 무엇이 필요함".

**되살리는 법**: 원인이 없어진 것을 확인한 뒤 `retry_count`를 0으로 둔 새 패킷으로 다시 시작합니다.
원인을 모른 채 재시도만 반복하는 것은 금지입니다(2번 고쳐도 안 되면 방법 바꾸기 — CLAUDE.md 4번).

**한도 보호**: 정해진 계산에 AI를 부르지 않습니다(5장). 큰 작업은 예약 시각(05:52·08:52·10:05·10:23·15:23·16:05·20:05)을 피합니다(AGENT.md).

## 7. 검증 게이트 (GPT 반박 + CI)

**PR을 올릴 때** `.github/pull_request_template.md`가 자동으로 붙습니다. 아래를 채웁니다.

| 칸 | 보는 것 |
|---|---|
| 보안 | 비밀키·토큰·매장 숫자·개인정보 없음, 무인증 쓰기(시트·배포·전송) 없음 |
| 성능 | 3초/10초 SLA 안에 드는가, 걸린 시간을 쟀는가 |
| 상태 머신·엣지케이스 | 화면마다 따로 판단하지 않고 `order-src/STATES.md` 상태를 쓰는가, 빈 자료·오류·늦은 응답을 시험했는가 |
| GPT 반박 검증 | 지적 목록과 반영/미반영 이유, `[GPT 검증 완료]` 판정 |
| 되돌릴 수 없는 일 | 배포·전송·결제가 있으면 KM 확인을 받았는가 |
| 시험 결과 | 돌린 명령과 결과(초 단위 시간 포함) |

**자동 검사** `.github/workflows/pr-check.yml` (PR 열림·고침, main 푸시마다):

1. `python3 tools/guard.py --all` — 비밀키·토큰·매장 자료·개인정보
2. `python3 tools/banned-words.py` — KM 지정 금지어
3. `python3 tools/ci-checks.py` — JSON·YAML 문법, 태스크 패킷 스키마
4. `node --test` — 저장소의 `*.test.mjs`

지금은 PR 본문 체크리스트가 비어 있으면 **경고만** 남기고 막지 않습니다.
막는 방식으로 바꿀지는 KM이 정합니다(바꾸면 `pr-checklist.py --strict`).

## 8. 이 문서를 고치는 법

1. 고칠 곳이 이 문서면 여기만 고칩니다. 다른 문서에 같은 말이 있으면 **이 문서를 가리키게** 바꿉니다.
2. 고친 날짜와 이유를 아래에 한 줄 남깁니다.
3. 금지어가 새로 정해지면 `tools/banned-words.py` 목록에 더합니다(그 단어 자체는 코드에 그대로 쓰지 않고 유니코드로 적어, 검사에 걸리지 않게 함).
