# 🤝 Aside Web Agent Task Generator

집 PC의 어사이드(Aside & Claude Code) 브라우저 에이전트가 실행할 작업 지시서
`docs/aside/tasks/task-*.md`를 규격에 맞게 생성하는 스킬.

## 1. 언제 이 스킬을 쓰나

- 사용자가 "어사이드한테 OO 시켜줘"라고 요청할 때
- 웹 리서치·스크린샷 수집·브라우저 조작 작업을 위임할 때
- 기존 task 파일의 진행 상태를 갱신할 때

## 2. 브릿지 파이프라인 (docs/aside/README.md)

```
폰의 피클 ── task-*.md 작성+push ──▶ GitHub docs/aside/tasks/
                                        │
집 PC 어사이드 ◀── 사용자가 "할 일 읽어" ──┘
        │ 실행 후 report-*.md 작성+push
        ▼
GitHub docs/aside/reports/ ── 피클 감지 ──▶ 사용자 폰 요약 알림
```

## 3. 지시서 규격 (docs/aside/tasks/task-*.md)

기존 실제 예시(`task-deploy-apps-script.md`)의 구조를 따른다:

```markdown
# [Task] <한 줄 작업명>

받는 사람: 어사이드 (집 PC 브라우저)
보낸 사람: 클로드 코드 / 피클
상태: 대기 | 진행 중 | 완료 | 보류 (이유)

## 무엇을
<작업 목적 1~3문장. "왜"가 아니라 "무엇을" 중심>

## 대상 (헷갈리기 쉬우니 꼭 확인)
<정확한 프로젝트/계정/URL/ID. 비슷한 다른 대상과 혼동 방지 표 + "❌ 건드리지 않음" 명시>

## 순서
1. <정확한 URL로 시작하는 단계>
2. <클릭할 버튼의 화면상 정확한 표기 (부모 메뉴 경로 포함)>
   - ⚠️ <하면 안 되는 것과 그 이유 (예: [새 배포] 누르면 39개 매장 앱이 끊김)>
...

## 확인
| 확인 | 방법 | 정상 기준 |
|---|---|---|

## 끝나면
1. 이 파일의 `상태:`를 `완료`로 고침
2. `docs/aside/reports/report-YYYYMMDD-주제.md`에 결과 기록
3. `docs/aside/board.md` 맨 아래에 `- 시:분 [어사이드 → 클로드 코드] 요약` 추가 후 push
```

## 4. 생성 규칙 (에이전트 실행 가능성 기준)

- **클릭 좌표가 아닌 정체성으로 지시:** 화면 크기가 다르므로 "좌표 (512,340) 클릭" 금지. 반드시 **보이는 텍스트/레이블/아이콘 이름 + 경로**로 지시. (`[배포] → [배포 관리] → 연필`)
- **대기 조건 명시:** 로딩이 필요한 단계엔 "결과 화면에 X가 보일 때까지 대기"로 지시. 고정 초 대기 지시 금지.
- **하나의 파일 = 하나의 작업.** 여러 작업을 묶으면 중단 시 어디까지 됐는지 알 수 없다.
- **되돌릴 수 없는 행동 앞에 ⚠️:** 삭제, 배포, 결제, 권한 승인류는 반드시 경고와 이유를 함께.
- **실패 시 행동 지시:** "X가 안 보이면 스크린샷을 남기고 중단, 보고서에 시도 내역 기록" — 임의 우회 금지.
- **스크린샷 캡처 지시:** 주요 단계 완료 후 스크린샷을 `docs/aside/reports/assets/`에 저장하고 보고서에 경로를 명시하도록 지시. 계정·개인정보가 보이는 화면은 마스킹 지시 포함.
- **보고서 규격 지시:** `report-YYYYMMDD-주제.md`에 (1) 결과 요약 3줄 (2) 단계별 확인 스크린샷 경로 (3) 실패/예외 내역 (4) 후속 제안.

## 5. 생성 절차 (피클/클로드 코드 측)

1. 작업 내용을 사용자 요구에서 확정 — 모호하면 이 스킬에서 생성하지 않고 확인 질문으로.
2. 대상의 정확한 식별자(URL, 배포 ID, 프로젝트명, 계정)를 저장소 문서/이전 보고서에서 수집. 없으면 "확인 필요" 표기 후 생성.
3. 위 규격으로 task 파일 작성, 파일명 `task-YYYYMMDD-주제.md` (기존 파일과 충돌 방지).
4. `docs/aside/board.md` 맨 아래에 `- 시:분 [클로드 코드 → 어사이드] 작업 의뢰` 추가.
5. git 커밋+push → 사용자에게 "어사이드에게 전달됨, 집 PC에서 실행 요청하면 됩니다" 안내.

## 6. 엣지 케이스 방어책

- [ ] 로그인/2단계 인증이 필요한 작업 → 지시서에 "로그인 창에서 대기, 사용자가 직접 완료" 명시. 자동 입력 시도 금지
- [ ] 결제·배포·삭제류는 실행 전 확인 단계를 지시서 안에 한 단계 더 넣는다
- [ ] 기존 task 파일 수정 시 원문을 지우지 말고 `상태:`와 결과 섹션만 갱신
- [ ] 어사이드가 못 하는 작업(스마트폰 전용, 계정 2FA 요구, 물리 작업)은 task 생성 금지 — 대안 보고
- [ ] board.md 컨벤션(화살표 방향 `[보내는 → 받는]`)을 지킨다
- [ ] 민감 정보(비밀번호, 카드)를 task 파일에 절대 기록하지 않는다

## 7. 클로드 코드 체크리스트

1. [ ] 대상 식별자(배포 ID, URL)가 검증된 출처에서 왔다
2. [ ] 모든 단계가 텍스트 정체성 기반이고 좌표 지시가 없다
3. [ ] 대기 조건과 실패 시 행동이 각 단계에 있다
4. [ ] 되돌릴 수 없는 행동에 ⚠️ 경고가 있다
5. [ ] 보고서 경로/규격과 board.md 갱신 지시가 포함됐다
6. [ ] push 후 커밋 해시를 사용자에게 보고했다
