# 💰 Daily Sales Gross & POS Reconciler

당일 POS 영수증 합계와 MIS 입력 매출의 차액을 1원 단위로 대사하고 원인을 추적하는 스킬.
`mis-sales.js`(MIS 자동화)로 읽은 MIS 매출과 POS 영수증 데이터를 대조한다.

## 1. 언제 이 스킬을 쓰나

- 매출 마감 후 POS 합계와 MIS 입력이 다를 때
- MIS에 잘못 입력(취소 누락, 프로모션 미반영)된 것을 찾을 때
- 일매출 보고 전에 최종 검증이 필요할 때

## 2. 대사 아키텍처

```
POS 영수증 로그          MIS 입력 매출           대사 엔진
┌───────────────┐      ┌───────────────┐      ┌─────────────────────┐
│ 영수증별 합계   │ ───▶ │ 일자별 총매출   │ ───▶ │ ① 총액 대사 (1원 단위) │
│ 결제수단별     │      │ 메뉴별 매출     │      │ ② 차액 원인 분해      │
│ 취소/반품 건   │      │ 할인/쿠폰 금액  │      │ ③ 역산 검증          │
└───────────────┘      └───────────────┘      └─────────────────────┘
```

## 3. 차액 원인 분해 (체크 순서)

차액 `Δ = MIS총매출 − POS총매출` 발견 시 **아래 순서로 하나씩 제거**한다. 동시에 여러 가설을 뒤섞지 않는다.

1. **취소/반품 누락:** POS에는 반영되고 MIS 입력에 빠진 취소 건 → Δ ≈ 취소 금액 합(음수)
2. **프로모션/쿠폰:** POS는 할인 후 실수령액, MIS는 정가 입력 → Δ ≈ 쿠폰/할인 합
3. **복합 결제 분할 오차:** 현금+카드 분할 입력 시 한쪽만 반영 → Δ ≈ 분할액 하나
4. **1원 단위 반올림:** 할인율 계산 원 단위 절사 차이 → Δ가 소액(건당 수원~수십원)이고 건수 곱이면 여기
5. **영수증 시간대 경계:** 영업일 기준 차이(마감 시각 23:59/24:00)로 전날·당일 건이 엇갈림 → 다음날 매출과 상쇄 확인
6. **중복 입력:** 동일 영수증이 두 번 입력 → Δ가 특정 금액의 2배인지 확인

```js
function reconcile({ posTotal, misTotal, posReceipts }) {
  const delta = misTotal - posTotal;
  if (delta === 0) return { ok: true, delta: 0 };
  const report = { delta, hypotheses: [] };
  const cancels = posReceipts.filter((r) => r.type === "취소");
  const cancelSum = cancels.reduce((a, r) => a + r.amount, 0);
  if (cancelSum && delta === -cancelSum) report.hypotheses.push("취소 누락 (MIS 미반영)");
  const roundDiff = posReceipts.reduce((a, r) => a + (r.rounding || 0), 0);
  if (roundDiff && Math.abs(delta - roundDiff) <= posReceipts.length) {
    report.hypotheses.push("원 단위 절사 누적");
  }
  report.hypotheses.push("시간대 경계(전영업일 상쇄) 및 복합결제 분할 확인 필요");
  return report;
}
```

## 4. 역산 로직

- MIS 총매출 − 취소 − 할인 = **순매출**과 POS 순매출 대조 (총매출만 맞으면 안 됨).
- 결제수단별 대조: 카드합·현금합이 각각 맞는지. 총액만 맞고 수단이 엇갈리면 입금 계좌 불일치로 이어짐.
- 영수증 건수 대조: MIS 입력 건수 = POS 영수증 건수. 금액이 같아도 건수가 다르면 상쇄 오류 의심.

## 5. 엣지 케이스 방어책

- [ ] 1원 단위 비교 — `Math.abs(delta) <= 1`도 "맞음"으로 처리하지 않고 원인을 남긴다
- [ ] 부동소수점 금지: 금액은 항상 정수(원)로 연산, 소수점 환율/할인율은 정수 퍼센트×금액 후 절사 규칙 명시
- [ ] 시간대 경계 차액은 당일만 보고 끝내지 말고 **다음날 마감에서 상쇄 여부까지 확인**
- [ ] POS 로그에 없는 MIS 입력(현금 영수증 직접 입력 등)은 "POS 외 입력"으로 분류, 오류 아님
- [ ] 대사 결과는 영수증 건 리스트(취소 건은 영수증 번호)까지 남긴다 — 다음날 재대사를 위해
- [ ] MIS 값은 `mis-sales.js`로 실제 화면에서 읽은 값이며, 기억/추정치로 대사하지 않는다

## 6. 클로드 코드 체크리스트

1. [ ] 총액·순매출·결제수단·건수 4개 축을 모두 대조했다
2. [ ] 차액 원인 분해를 순서대로 하나씩 적용하고 제거 근거를 남겼다
3. [ ] 금액 연산이 전부 정수(원) 단위다
4. [ ] 시간대 경계 건은 다음 영업일 상쇄 확인까지 따라갔다
5. [ ] "POS 외 입력"과 "오류"를 구분해 보고했다
6. [ ] 기준 영업일과 데이터 수집 시각을 표기했다
