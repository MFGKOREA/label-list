# 👥 Store Roster & PLJEC HR Shift Parser

주간 근무표(텍스트·표·스크린샷 붙여넣기)를 구조화하고, 포지션별 인건비율을 계산하며,
금요일·토요일·일요일 피크 타임의 인력 공백을 진단하는 스킬.

## 1. 언제 이 스킬을 쓰나

- 본사/점포 주간 근무표(이미지·엑셀·텍스트)를 받아 구조화할 때
- 주간 인건비율(Labor%)과 포지션별 배치 적정성을 점검할 때
- 금토일 피크 시간대에 오픈/미들/마감 인원이 비는 구간을 찾을 때
- 근무표 변경(휴무·대타) 후 인건비와 커버리지 재계산이 필요할 때

## 2. 파싱 규격

근무표 원문은 형식이 매번 다르므로, **토큰 사전 → 행 파싱 → 검증** 3단계로 처리한다.

```js
// 1단계: 근무 유형 토큰 사전 (매장별 변형을 여기에 추가)
const SHIFT_TOKENS = {
  O:  { label: "오픈",   start: "09:30", end: "17:00" },
  M:  { label: "미들",   start: "12:00", end: "18:00" },
  C:  { label: "마감",   start: "17:00", end: "23:30" },
  OC: { label: "오픈마감", start: "09:30", end: "23:30" }, // 휴게 별도 확인
  X:  { label: "휴무" },
  V:  { label: "휴가" },
};

// 2단계: 한 행 = [이름] + 요일별 토큰 (요일 헤더에서 매핑)
function parseRosterRow(line, dayHeaders) {
  const cells = line.split(/\t|\s{2,}|\|/).map((s) => s.trim()).filter(Boolean);
  const name = cells[0];
  const shifts = {};
  cells.slice(1).forEach((tok, i) => {
    const key = SHIFT_TOKENS[tok.toUpperCase()] ? tok.toUpperCase() : null;
    if (!key && tok && tok !== "-") {
      shifts[dayHeaders[i]] = { raw: tok, error: "미등록 토큰" };  // 조용히 버리지 않는다
    } else if (key) {
      shifts[dayHeaders[i]] = { ...SHIFT_TOKENS[key], hours: hoursOf(SHIFT_TOKENS[key]) };
    }
  });
  return { name, shifts };
}
```

- 요일 헤더(월~일)를 먼저 찾고 없으면 파싱을 시작하지 않는다. 열 개수와 요일 수 불일치 → 즉시 실패 보고.
- 근무 시간 계산은 **휴게시간 제외(식사 30분/휴게 30분, 5시간 이상 근무 시 1시간)** 가정을 명시하고, 본사 기준과 다르면 사전에 확인.
- 주 52시간(연장 포함 주 12시간) 초과 여부를 항상 검사한다.

## 3. 인건비율(Labor Cost%) 계산

```js
function laborPct({ hourlyWages, rosterHours, sales }) {
  const cost = Object.entries(rosterHours).reduce(
    (sum, [name, h]) => sum + h * (hourlyWages[name] || 0), 0
  ) * 1.0; // 4대보험/시상 등은 별도 레이트, 필요 시 multiplier 옵션
  return { cost, labor_pct: sales > 0 ? cost / sales : null };
}
```

- 분모 매출은 **MIS 일자별 매출** 기준(`sales-gross-reconciler` 스킬로 검증된 수치). POS 추정치와 섞지 않는다.
- 포지션별 분석: 오픈(오픈 준비+런치 인입), 미들(런치↔디너 전환), 마감(디너 피크+마감 정리)로 시간대 인원을 합산.

## 4. 피크 시간대 공백 진단 패턴

```
시간대 커버리지 매트릭스 (예)
시간      | 월  화  수  목  금  토  일
11:00-12  | 2   2   2   2   3   4   3
12:00-14  | 3   3   3   3   5   6   5   ← 런치 피크
17:00-19  | 2   2   2   3   5   7   5   ← 디너 인입
19:00-21  | 2   2   2   3   6   8   6   ← 디너 피크
```

진단 규칙(모두 명시적으로 보고):
- **금토일 18:00~21:00 최소 인원 기준** 미달 → 공백 플래그 (기준 인원은 매장 설정값, 없으면 "미설정"으로 보고)
- 마감 인원 1인뿐인 날(안전·마감 품질 리스크) 플래그
- 오픈 인원 1인뿐인 날(오전 준비 지연 리스크) 플래그
- 연속 6일 근무 / 주 52시간 초과 / 야간 마감 직후 다음날 오픈(피로 누적) 플래그
- 미들 공백(14:00~17:00)은 매출 피크가 아니므로 정보 수준으로만 표기

## 5. 엣지 케이스 방어책

- [ ] 미등록 토큰(예: `ㅇ`, `D`, 숫자) → 오류로 표기하고 원문 그대로 보존, 임의 해석 금지
- [ ] 병합 셀/줄바꿈된 표(스크린샷 OCR) → 이름-요일 정렬이 깨지면 파싱 중단 후 원문 첨부 요청
- [ ] 동명이인 → 구분자(닉네임/직급) 없이는 병합 금지, 질문 플래그
- [ ] 시급 데이터 없음 → 인건비 절대액 계산 생략하고 시간 커버리지 분석만 제공
- [ ] 개인정보: 근무표의 이름·시급은 리포트 목적 외 사용 금지, 외부로 전송하지 않는다 (본사 시스템 입력이 필요한 경우 사용자 확인)
- [ ] 대타/추가 근무 후기입 → 원본을 덮어쓰지 말고 변경 이력 행을 추가

## 6. 클로드 코드 체크리스트

1. [ ] 요일 헤더 검증을 통과한 뒤에만 파싱 결과를 확정했다
2. [ ] 미등록 토큰·불명 시급을 오류로 명시했다 (추정 채움 없음)
3. [ ] 인건비율의 분모 매출 출처를 표기했다
4. [ ] 52시간/연속근무/단독오픈·마감 플래그를 검사했다
5. [ ] 개인정보(이름·시급)를 목적 외 노출하지 않았다
6. [ ] 리포트에 기준 주차(YYYY-MM-DD 주)를 명시했다
